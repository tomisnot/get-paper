## 1. 范围与双界面模型 🆕（本轮明确）

用户预想打开**两个界面**，据此划定本项目边界：

| 界面 | 内容 | 归属 | 本项目是否做 |
| --- | --- | --- | --- |
| **界面① · AI 交互 / 监视 AI** | 与 AI 对话、看 AI 在干什么 | 用户既有项目已能承担 | ❌ **不做**（含"AI 如何接入/衔接"也一并暂缓） |
| **界面② · 可视化界面** | AI 总结、调查结果显示于此；人也可直接操作 | 本项目 | ✅ **做** |
| **手脚 · 能力/工具层** | 文献调研全流程里可固化的操作 | 本项目 | ✅ **做（本轮核心）** |

**一句话边界**：我们建"**手脚（工具）+ 可视化界面②**"，不建"AI 大脑接入 + 界面①"。
手脚要整理成**适合外部调用的中性形式**（见 §4），供界面①里的 AI 来调；本轮**不选任何 AI 协议**、不受旧仓库 MCP/DSH 方向影响。

---

## 2. 终极形态 🆕（本轮明确）

> 文献调研全流程：**能固化的操作 → 写成程序（工具）；不好固化的环节 → 交给 AI；理想情况下 AI 还能据自身使用体验进一步迭代。**

- "固化 vs 交给 AI"的判据见 [`PRINCIPLES.md`](PRINCIPLES.md) §3（数据量大/步骤固定/需精确/高频 → 固化；判断/编排/语言 → AI）。
- 本节把该判据落到文献调研的每个环节，见 §3。

## 3. 能力（工具）清单 —— 到底实现哪些 🆕

> 动作：把上述能力从"绑死 MCP"改为经**连接层**暴露（§4），逻辑原样复用。

### 3.2 缺失、要新建（补齐闭环与调研深度）

| # | 能力 | 为什么要 | 优先级 |
| --- | --- | --- | --- |
| N1 | **下载 PDF 并归档** `download_paper(arxiv_id)` | 用户核心动作"点进去下载"（原来只外链 pdf_url） | ✅ **已落地**(P0) |
| N2 | **全文解析**（供精读） | 精读问答/深度总结需要全文，原来只有 abstract | ✅ **已落地（2026-09-29，改走 HTML 而非 PDF）**：`fetch_paper_html` 归档 arXiv HTML 正文（剥脚本、全量离线）→ `read_paper_outline`/`read_paper_text`/`search_paper_text` 分节取用 → `annotate_paper` 在**原文上**落带位置的批注 → `/read/{id}` 精读页 + `capture_paper_shot` 无头截图回看。**没有 HTML 的论文不进精读体系**（不回落 PDF：PDF 没有锚点，标不住） |
| N3 | **细粒度画像维护** `update_profile`（增删改关键词/权重/排除词/给某方向降权） | 现在只能加/停整个主题，无法对话式微调品味（承信条 7、§4.2 宪法） | P1 |
| N4 | **相似/相关论文** `similar_papers(arxiv_id)` | 顺藤摸瓜是文献调研高频动作 | P2 |
| N5 | **语义/embedding 检索** `semantic_search` | FTS5 只能关键词，语义召回是漏斗第②层（宪法 §5.2） | P2 |
| N6 | **外部质量信号**（Semantic Scholar 引用数/TLDR） | arXiv 影响力数据弱，用于排权重（不换源，承宪法 §7） | ✅ **已落地**（`paper_metrics`） |
| N7 | **导出 BibTeX / Markdown 引用** | 调研沉淀常用 | P2 |
| N8 | **趋势取数** `trend(keyword/author)` | 捕捉领域风向 | P3 |

### 3.3 明确"留给 AI、不固化"的环节（写程序反而是错的）

- 语义相关性判断（这篇值不值得看）
- 结构化精读总结 + **"为什么推荐给你"的理由**（关联画像）
- 单篇深度问答 / 方法拆解 / 翻译
- 自然语言 → 画像改动的**翻译**（写入本身由 N3 固化，翻译与确认话术归 AI）
- 多工具的编排调度（先抓再筛再下载…）

### 3.4 AI 自我迭代方向 🆕（aspirational · P3）

- **固化 telemetry**：工具调用、用户反馈（已读/收藏/跳过/下载）已有 `events` 基础 → 结构化留存。
- **AI 复盘**：AI 定期分析"哪些推荐被忽略/哪些被下载精读"，**提议**画像或流程改进（**人确认后**才落库，承信条 4）。
- 参考开源 `ScienceClaw`（agent 据研究模式自主写新 SKILL.md）——但我们**保守版**：AI 只"提议"，不自动改自己的工具。

### 3.5 专项调查 / 引文分析能力 ✅（新增方向，已落地）

> 与"每日日报"不同的**另一种使用模式**：用户拿到一篇论文做专项调查时，AI 用这些手脚去扒脉络。数据源 = **Semantic Scholar**（arXiv 自己几乎没有引文数据）。

| 能力 | 作用 | 状态 |
| --- | --- | --- |
| `paper_metrics(arxiv_id)` | 影响力度量：被引数/参考数/高影响引用数/年份/venue/TLDR（质量信号，= N6） | ✅ |
| `get_references(arxiv_id, limit, sort_by_citations)` | 它引用的文献，**默认按引用数降序**——排最前的即"起源/奠基"候选；含 intents/是否高影响引用 | ✅ |
| `get_citations(arxiv_id, limit)` | 引用了它的文献（往后看影响力扩散/后续工作） | ✅ |

**典型工作流（"这个技术从哪来"）**：`get_references(论文)` → 高被引+年份早的即起源候选 → 对候选**递归** `get_references` 继续往前扒 → **AI 结合这些引文数据 + 自己的搜索，综合出"起源脉络"结论**（综合与判断留给 AI，见 §3.3；工具只负责确定性地取引文数据）。

**运维**：S2 公共端点无 key 时限速较严（易 429）；客户端已做限速+退避重试+7天磁盘缓存+429/404 优雅降级（返回可教学错误）。配 `SEMANTIC_SCHOLAR_API_KEY`（免费）可显著提升配额。

**留给 AI/后续**：多跳自动溯源、引文图谱可视化、"结合搜索"的综合叙事——待 AI 接入阶段。

## 4. "适合外部调用的形式" ✅（已确认）

> ✅ **用户已拍板**：采用 **Python API + CLI(`--json`)** 两个门面；暂不加纯 HTTP API，也不以 MCP 为对外中心。
> 目标：能力实现出来、整理成**任何外部调用方都能用**的形式，但**本轮不绑定任何 AI 协议**。

- **连接层**：每个能力 = 一个 typed、self-describing 的工具，带元数据：`name / description / 入参 JSON-schema / 结构化返回 / read|write / reversible`。
- **统一返回信封**：`{ok, data | error{kind,hint,suggest}, meta}`；沿用仓库已验证的**体积闸**（大回程截断并告知去哪看全量）与**可教学错误**，但**与 MCP 解耦**。
- **两个 protocol-agnostic 门面**：
  1. **Python API**：`import` 直接调 —— 供可视化界面②与任何进程内消费者。
  2. **CLI（`--json`）**：`paperpilot <tool> ... --json` —— 供**任意外部进程/harness**（含界面①的 AI）用 subprocess 调用，无需我们选协议。
- **旧 MCP server**：日后可作为这个中性层之上的**一个薄 adapter**存在；本轮**不动 AI 接入**，也不以它为设计中心。

## 5. 可视化界面②（要实现的界面）

### 5.1 每日日报视图（第一个落地）

- ✅ **逐条列出，每条 = 一篇论文**
- ✅ 每条含 **AI 总结，尤其"为什么我要看这篇"**（关联画像；已做成醒目 callout「💡 为什么推荐给你」，前置于 TL;DR/方法之上）
- ✅ 每条含 **直达该论文的链接**（arXiv 原文）
- ✅ 每条含 **下载按钮**（对应 N1，接上"看到→下载"核心闭环）
- ✅ 每条含 **相关性评分 / 标签**
- ✅ 每条含 **一句话 TL;DR**
- ❌ 暂不在每条内嵌"已读/收藏"操作（本轮未选；详情页仍可操作）
- 🚧 待细化：排序/分组、顶部统计条、空态、探索配额区

### 5.2 其他视图（仓库已有雏形，按新基调对齐）

| 视图 | 现状 | 说明 |
| --- | --- | --- |
| 论文库 / 检索 | `papers.html` 已有 | 对齐 N4/N5 后增强 |
| 论文详情 | `paper_detail.html` 已有 | 摘要+AI总结+理由+笔记；**已补「📖 精读正文」入口**（有 HTML 时才出现；没有则显"不进精读"） |
| **精读页** | ✅ **新增（2026-09-29）** `/read/{arxiv_id}` | 正文（**本站同源** iframe，无脚本）+ 批注层 + 侧栏；AI 的批注经增量接口**每 4 秒自动上屏**；人可删批注。无 HTML 的论文如实说明并指路 |
| 画像 / 主题 | `settings.html` 已有 | 从"表单 CRUD"演进为"可视化 + 人可改 + 显示 AI 建议"（N3） |
| 活动 / 记录仪 | `activity.html` 已有 | **让"AI 操作看得见"**（承信条 8）：before→after 已改为可折叠 + 美化 JSON（中文正常、不再撑爆行高） |

### 5.3 人机共享（承信条 8）

- 人在界面②直接操作：阅读、点链接、下载、标记已读/收藏/跳过、加笔记、改画像、**精读时删批注**。
- AI 经工具改**同一份内部状态**；界面②应**实时反映**（事件驱动 / 局部刷新），看得到"AI 刚做了什么"。
  - ✅ **精读页已兑现"实时"**（2026-09-29）：阅读页轮询 `/read/{id}/marks.json?since_id=`，AI 落一条批注就上一次屏。
  - 🚧 其余页面（简报/论文库）仍需手动刷新。
- 所有写入带 `actor/reason`、可 `undo`。

## 7. 决策记录（本轮已拍板）

- ✅ **外部调用形式** = Python API + CLI(`--json`)，暂不加 HTTP、不以 MCP 为中心（§4）。
- ✅ **首个里程碑** = P0 全部：能力层重暴露 + `download_paper` + 日报视图（§6）。
- ✅ **日报每条** = AI 总结(为什么看) + 直达链接 + 下载按钮 + 相关性评分/标签 + 一句话 TL;DR（§5.1）。
- 🚧 **下载策略（默认）**：PDF 存本地 `data/`（在同步盘内天然备份）；如有版权/存储顾虑再调整（N1）。
- ❓ **语义检索/embedding**：留到 P2 再定（本地小模型 vs 外部 API）（N5）。
