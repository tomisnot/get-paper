# PaperPilot 开发者指南

PaperPilot 将论文领域模型、抓取和研究工作流保留在项目中，通过 mecha 接入统一命令、工具、账和监控。

## 代码结构

| 区域 | 职责 |
|---|---|
| `src/paperpilot/domain/` | 论文、画像、评审和简报领域模型与流程 |
| `src/paperpilot/capabilities/` | 自描述能力及其 Python 调用层 |
| `src/paperpilot/infra/` | SQLite、FTS5、arXiv、Semantic Scholar、渲染和账本 |
| `src/paperpilot/mecha_adapter/` | 命令注册、工具投影、Gate 配置校验和 MCP 接线 |
| `src/paperpilot/app/` | CLI、Web、容器和运行入口 |

## 状态与账

SQLite 业务表保存当前物化状态，`events` 表保存事实。GP 的配置、业务事件和命令结果使用同一事件落点；事件带 `seq`、`operation_id`、`role`、操作者、理由、前后像和结果引用。`role` 区分操作、业务变化和派生判断。

`History` 通过注入的 `SqlLedger` 读取同一事实流；它提供读取、追加和配置投影，不另建第二本逻辑账。业务表和事件表在同一事务内维护，领域投影由 GP 自己实现。

## 能力与命令

能力声明集中在 `capabilities/tools.py`，`mecha_adapter/tools.py` 将其投影成工具；写能力同时生成 `CommandSpec`。`run_pipeline` 是 GP 给人和调度器使用的确定性命令，AI 面使用 `fetch → prepare → submit → finalize` 的评审流程。

配置标量由 `CONFIG_SCHEMA` 和 Gate 校验，主题、论文、评审和简报等变长业务状态走领域命令。所有命令共享操作关联、写权、审计和结构化错误。

## 外部 AI 边界

项目不维护模型客户端、供应商、API key 或模型地址。`infra/ai/baseline.py` 只提供确定性基线；内容判断由外部 AI 完成并以派生事实写回。工具层保持协议中立，MCP 是当前宿主适配器，不是领域层。

## 修改原则

论文语义、评分策略和渲染属于 GP；治理、操作关联、事实序列和通用回执属于 mecha。新增能力先放进 `capabilities`，再由适配层投影；不要在 Web、CLI、MCP 各写一套业务实现。
