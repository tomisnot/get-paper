# PaperPilot 开发者指南

PaperPilot 是论文情报和研究工作台。它把论文抓取、研究主题、画像、评分、评审、简报、阅读状态、笔记、标签和引文图组织为一个长期可查询的领域系统。mecha_adapter 负责统一命令、查询、写权、操作账和工具投影；领域代码不依赖 MCP 或网页协议。

## 1. 分层

| 目录 | 当前职责 |
|---|---|
| src/paperpilot/domain/models.py | Paper、Topic、Review、Briefing、Reading、Run 等领域模型 |
| src/paperpilot/domain/policy.py | 主题过滤、规则 Gate、评分和简报选择策略 |
| src/paperpilot/domain/profile.py | 研究画像、特征、权重和相关性 |
| src/paperpilot/domain/feed.py | feed 候选与日报流程 |
| src/paperpilot/domain/graph.py | 引文图、共引和视图规格 |
| src/paperpilot/domain/pipeline.py | fetch、评审、简报等阶段编排 |
| src/paperpilot/domain/services.py | 检索、论文详情、阅读状态和笔记服务 |
| src/paperpilot/infra/repo.py | 业务持久化、事件、全文、评分、简报和图 |
| src/paperpilot/infra/db.py、orm.py | SQLite 会话、表和事务 |
| src/paperpilot/infra/ledger.py | 账本接口和操作关联 |
| src/paperpilot/infra/arxiv.py、scholar.py | 外部论文与引文服务 |
| src/paperpilot/infra/ai/ | 确定性基线和 AI 错误边界 |
| src/paperpilot/capabilities/ | 能力声明与项目领域调用层 |
| src/paperpilot/mecha_adapter/ | 命令、Scope、工具、控制和监控 |
| src/paperpilot/app/ | CLI、Web、容器和页面 |

app/container.py 是依赖装配入口；main.py、cli.py 和 web.py 是宿主入口。

## 2. 数据与账

SQLite 物化表保存当前查询所需状态，events 保存追加事实。PaperPilot 的业务事件至少带 seq、operation_id、role、actor、reason、before/after 或结果引用。role 区分操作、业务变化和派生判断。

PaperRepository 在同一事务边界中维护业务表和事件。它负责 topics、papers、scores、summaries、briefings、runs、AI calls、reading、notes、tags、HTML、全文索引、citation edges 和 graph views。

账是追踪和重建依据，不是把全部领域对象塞入 mecha History。mecha_adapter 读取 SqlLedger 或注入的账接口，将治理操作与 PaperPilot 业务事件关联。

## 3. 领域流程

### 抓取

arxiv.py 和 scholar.py 负责外部请求、缓存、速率和结构化解析。domain/feed.py 根据 enabled topics、lookback 和去重规则生成候选。抓取结果先进入论文库，再进入主题池。

### 评分与画像

policy.py 提供关键词、作者、分类、时间和规则 Gate。profile.py 根据论文特征和用户信号生成权重和相关性。评分是可解释的派生数据，保存输入特征、策略和时间。

### 评审与简报

pipeline.py 编排 fetch、prepare review、submit review 和 finalize briefing。prepare 阶段返回候选、规则分、理由和输出契约。外部 AI 的判断以结构化评审写入；finalize 只消费已保存的评审和评分，生成简报与卡片。

确定性基线属于 fallback，不伪装成模型判断。没有 AI 时仍可运行规则筛选和人工流程。

### 阅读和图

services.py 提供搜索、详情、已读、星标、跳过、笔记和标签。graph.py/repo.py 保存引文边、共引关系和用户图视图。paperhtml.py、fts.py 和 render.py 负责 HTML、全文块和渲染。

## 4. 能力声明与 mecha 适配

capabilities/tools.py 保存项目能力和参数。mecha_adapter/tools.py 将能力声明投影为工具，并通过 command bridge 统一执行。

写能力通常分为：

- 配置：主题、抓取窗口、画像或显示设置；
- 领域操作：同步主题、抓取、评审、简报、标签、阅读状态；
- 读取：论文、评分、引文、全文、简报和活动；
- 管理：撤销、重置、删除和 graph view。

工具层不在网页或 CLI 中复制领域逻辑。每个写能力应同时有 command、scope、操作理由和结构化错误。

## 5. 评审契约

prepare_review 的回执要能让外部 AI 在没有隐藏状态的情况下完成判断。它至少包含论文 id、标题、摘要/正文引用、规则分、匹配关键词/作者、输出字段和提交约束。

submit_review 校验：

- 论文 id 存在；
- 评审批次和主题匹配；
- 分数、标签、理由和必要摘要类型正确；
- 不接受未知字段；
- 重复提交有明确策略；
- 结果和 AI 调用可追踪。

finalize_briefing 只处理已保存评审。它应返回 briefing id、日期、项目数和生成结果引用。

## 6. 写入、撤销与审计

所有写入经过 ScopePolicy、Gate 和命令 bridge。operation_id 贯通 mecha History、PaperRepository 事件和结果引用。reason 用来解释动作意图，外部发送、删除、重置和批量状态变更需要更明确的理由。

undo 或 reset 不直接删除事实；它们追加新的业务事件并重建物化状态。读取接口应能显示事件、当前状态和必要依据。

## 7. 外部服务

SemanticScholarClient 负责 API key、缓存、速率、重试和字段选择。arXiv 获取与 PDF/HTML 下载属于 infra；领域服务只依赖端口或仓储接口。外部服务失败必须有明确 error_kind、hint 和可重试信息，不能写成空论文。

## 8. 新增领域能力

1. 先在 domain 中定义对象、服务和规则；
2. 在 infra/repo.py 增加事务持久化和事件；
3. 在 capabilities 声明参数、回执和错误；
4. 在 mecha_adapter/commands.py 接入操作；
5. 在 tools.py 投影查询和命令；
6. 在 CLI/Web 中复用同一服务；
7. 增加库级、适配层和端到端测试；
8. 更新用户手册和能力说明。

不要把论文语义放入 mecha 核心，也不要让 Web 路由直接写 ORM。

## 10. 维护规则

领域服务保持协议中立；MCP、CLI 和 Web 只是适配器。物化表是高效读模型，events 是追溯依据；派生评分和简报可重算。外部 AI 的判断必须显式保存，基线必须标明确定性来源。
