## 1. 一句话：这个仓是什么、给谁解决什么问题

**PaperPilot 是一个"人机共享的本地论文情报工作台"**：把 arXiv 新论文抓进本地库，让 AI 通过工具
**筛选、精读、写成每日简报**；人和 AI 操作**同一份内部状态**、走**同一道写权门**、留**同一本账**。

- **给谁**：一个研究者自己用 —— 单机、无服务端、数据全在本地 `data/`。
- **不做什么**：软件内**不接 LLM key**。内置 AI 档位只是"无人兜底"（heuristic）；**真正的内容生产者是对话里的 AI**
  （`.agents/skills/paperpilot/SKILL.md` §0）。
- **三个面**：**Web 面板**（人看 / 人写）· **MCP 工具面**（AI 调）· **cockpit 监控**（AI 干了什么）。
  用法见 `README.md:64-94`、`README.md:131-170`。

## 5. ⭐ 跟着一条数据流走一遍

### 5.1 AI 写一次（例：AI 给一篇论文加笔记）

```
dsh 对话里模型决定调工具
 └─ dsh 插件（dsh/，Cordis）桥接 MCP、原生注册工具            → dsh/src/*
     └─ mecha 的 MCP 端点（hub.py:119 build_mcp_server；只监听 localhost）
         └─ mecha ToolRegistry.execute(...)                   ← 框架负责失败/回执归一化
             └─ 本仓写入工具的 execute = _make_command_bridge  tools.py:448
                 └─ invoke_command(...)                       commands.py:64
                     └─ 框架 CommandRegistry.invoke
                         ├─ ① 写权前置检查（框架在调 handler **之前**做；被拒 ⇒ 域写根本没发生）
                         ├─ ② scope 检查（允许表 scopes.py:37）
                         └─ ③ handler = _make_handler          commands.py:373
                              ├─ 配置叠加 gate_scoring_override engine.py:39
                              └─ capabilities.invoke(...)       capabilities/__init__.py:37
                                   └─ 领域实现                  capabilities/tools.py（该能力函数）
                                        └─ repo.*               infra/repo.py
                                             └─ SQLite 表 + 一条 events 行（**同一事务**）
```

**落库 / 出口**：状态进 `data/paperpilot.sqlite3`（`config.py:153` `Settings.db_path`）；同时落**两类账**：

- **域事件**进 `events` 表（`actor`/`reason`/`before`/`after`/`call_id`/`undoable`）——写口在 `repo.record_op`（`repo.py:856`）与各写操作内；
- **框架审计**（`command.<name>`）也进**同一张表**：装配时 `log_sink=container.repo.ledger`（`hub.py:97`）把 mecha 的账接到本仓；`SqlLedger` 见 `ledger.py:47`。

⚠ 两条账**同表同序列**不是巧合：`SqlLedger.append` 若发现"在途 session"就跟着调用方一起提交
（`ledger.py:38` `ledger_session`、`ledger.py:71` `append`）⇒ 域状态与账**不可能一个有一个没有**。

## 6. 改代码前必须知道的坑

**① 两块主干的分工，一句话记住**
`capabilities/` = 声明与实现（**一个事实一个家**）；`mecha_adapter/` = **两个面**。
⇒ **一份声明驱动两个面 —— 命令面（写治理）+ 工具面（AI 可见）**（那张唯一的表是 `tools.py:62` 的 `TOOL_DECLS`）。
**新增能力 = 加一条声明 + 一个能力函数**，别再手写 `define_tool`（投影已统一接管，见 `tools.py:343`）。

**② 命令面 = 写治理面；只读命令**刻意**不进命令面，别当漏做**
它的不变式是"**命令面里每一条都是写命令**"（要本次通道 / 要 `reason` / 要非零耗时预估）。
读命令没有写权、没有审计、`scope` 也没有运行时语义 ⇒ 它进那个面**只为投影**，却会让上面那条不变式变成假的。
⇒ 在 `build_commands`（`commands.py:408`）里看不到读命令 = **正常**。理由与实测写在 `commands.py:146` 的 docstring。
⇒ ⚠ 别为了"对称"把读命令注册进去：那会当场弄红**钉着这条不变式**的判据 ——
`tests/test_mecha_adapter.py:319`（写命令的声明契约）与 `check/test_ai_experience.py:167`（写命令的非零预估）。

**③ `scope` 的粒度 = 运行期闸的粒度（本仓踩过两次）**
两条命令共用一个 `scope` ⇒ 其中一条会**搭另一条的便车**。本仓真发生过：`delete_note` 挂过 `library`、
`set_config_batch` 挂过 `config`（两者都对 AI 放行）⇒ 运行期 AI **真能**删笔记 / 整表单写。

**④ "看不见"有两种表达，别混**

允许表在 `scopes.py:37`；`mecha_adapter/scopes.py` 顶部讲清了"这批绑定几乎等于空操作，价值在声明变规则"。

**⑥ 账：本仓把 mecha 的账落进自己的 `events` 表（不是写框架的 JSONL）**
- **谁写**：域写走 `repo.*`；框架审计走 `SqlLedger.append`（`ledger.py:71`）。

- **append-only 由数据库触发器钉死**（`db.py:149-162`）：任何 `UPDATE`/`DELETE events` 都被 `ABORT`
  ⇒ **想"改账"没门，只能追加**；手工修数据前先想清楚这一条。

**⑦ 数据库迁移有三种情况 —— 第二种会咬人**（都在 `infra/db.py`，`init_db` 里按顺序跑）

| 情况 | 做法 | 坑 |
| --- | --- | --- |
| **加列** | `_ADDED_COLUMNS`（`db.py:29`）+ `ALTER TABLE … ADD COLUMN … DEFAULT` | 老行**自动**拿默认值 ⇒ 默认值必须对老家底**语义正确**，否则静默错数据 |
| **改名** | `_RENAMED_COLUMNS`（`db.py:45`）+ `RENAME COLUMN` | ⚠ **老列的约束会跟着新名字继承下来**（如 `NOT NULL`）；`RENAME` 会顺带更新触发器/视图引用 |
| **改可空性** | `_NULLABLE_REPAIRS`（`db.py:55`）⇒ **只能重建表**（SQLite 不支持改可空性） | 本仓真踩过：`reversible`→`undoable` 改名后 `NOT NULL` 留下 ⇒ 插 `None` 时 `IntegrityError`。修法：按 **ORM** 建新表 → 搬数据 → 换名（`db.py:60`），**别手写 DDL** |

⇒ 改完 schema，**拿一个老库**开一次（不是删库重来）才算验过。

- **账**：**本仓**把 mecha 的账落进**自己的域库**——`log_sink=container.repo.ledger`（`hub.py:97`）
  ⇒ 框架的 `command.*` 审计与本仓域事件**同表、同序列、同事务**。
  ⚠ **这是本仓的选择，不是通则**：框架允许"项目把账写进自己的库"（`log_sink` 就是那个注入点），
  **另两个仓用的是框架默认的 JSONL 落点** ⇒ 别拿本仓的接法去套别人。
- **端口**：三个文件别混——
  - `.mcp-port`：MCP 端点起来后写（服务名见 `hub.py:37`，**仅监听 localhost**）；**dsh / AI 客户端**读。
  - `.web-port`：**本仓 Web 真 listen 之后**才写；**dsh 面板**读它（`panel-config.ts` 的 `PORT_FILE='.web-port'`），
    经同源只读路由 `/paperpilot/monitor-url` 拿到 base。
  - `.cockpit-port`：`start_cockpit` 写（框架 `MonitorEndpoint`）；⚠ **本仓没有代码读它**——面板走的是 `.web-port`
    ⇒ 它是给**人 / 别的工具**用的独立只读监控端点。

  ⇒ **本仓 Web 进程自己提供 `/history`（`web.py:889`）与 `/config`（`web.py:901`）**（cockpit 契约 JSON + CORS；
  未接栈时给 503 可读错误）；`/activity` 在 Web 侧是**给人看的 HTML 页**（`web.py:757`），`/status` 在 Web 侧**没有**路由
  ⇒ 面板对那几条路由是"**拿到几条算几条、缺的如实显示**"，不是"必须全绿"。
- **协议**：MCP = streamable-http；工具是**能力的薄封装**（写工具经命令面）。
  另有一层**不是框架的一部分**：本仓 `dsh/` 是 **DSH（DeepSeek Harness）的插件**（自愈 MCP 桥 + 右栏面板，见 §9.1）。
