# 从旧版吸收的机制（清单）

> 新版骨架定型后，回旧仓挖了一遍"让 AI 用着舒服、省 token、少犯错"的具体做法。
> 本文只记**拿回来了什么、为什么**，以及**明确不拿的**——免得后人在旧仓里再走一遍。

## 拿回来的

| 机制 | 旧版做法 | 新版落点 | 为什么值得拿 |
|---|---|---|---|
| **回程体积闸** | `base.gate()`：长列表截到 20 条，附 `_<key>_truncated{kept,total,where}`；整体超预算再收 | [limits.py](../src/paperpilot/mecha_adapter/limits.py)，读工具与命令回执统一过闸 | 一次 `limit=200` 能把上下文烧掉一半，而模型真正需要的往往只是"前十行 + 有多长"。**截断必须说出来**，不能静默丢 |
| **分页续读** | `read_paper_text` 回 `truncated / total_blocks / next_offset / where` | `query_papers` 回 `offset` 与 `next_offset`；`where` 写明还剩多少 | 让"续读"是一次明确的调用，而不是重猜参数 |
| **参数描述兜底** | 靠人写在 `params_desc` 里，漏了没人管 | [params.py](../src/paperpilot/mecha_adapter/params.py)：手写优先 → 常用表补 → 补不出来**构建期就炸** | schema 的 `description` 是模型唯一的用法来源；漏了就是让模型猜 |
| **写回执带下一步** | 回执末尾 `hint=` 告诉你接着调什么 | `fetch_paper` / `write_card` / `record_signal` / `set_config` | 省掉一次"我该干什么"的往返 |
| **可教学错误** | 统一 `{kind, message, hint, suggest}` | 已是信封形状；本轮补了 `arxiv_unavailable`（外部服务连不上不该报 `internal_error`） | 模型看到"内部错误"只会重试；看到 hint 才知道不用重试 |

## 这轮新长的（旧版没有）

| 机制 | 症状 | 落点 |
|---|---|---|
| **`None` → 默认值** | MCP 签名是**按 schema 合成**的，不带 Python 默认值 ⇒ 没传的可选参数以 `None` 到达，`int(None)` / `None.strip()` 炸成 `internal_error` | [args.py](../src/paperpilot/mecha_adapter/args.py)，命令与只读工具都盖到 |
| **`payload` 声明成对象** | 宿主会把"长得像 JSON 的字符串"解析成对象后再送进来；声明成 string 会在 pydantic 校验阶段被拒 | `write_draft` 的 schema |
| **配置 seed 幂等** | `Gate.seed` 每调一次写一条事件，而软件每次启动都 seed 一遍 ⇒ 事件流被「9 个键 × 每次重启」淹没，`read_activity` 全是 `set page_size 50` | `config.seed()` 只在值变了时才写 |

## 明确不拿的

| 旧机制 | 为什么不拿 |
|---|---|
| `undo_change(seq)` | 要回滚就得存前后像**并定义领域回滚语义**（删掉的卡怎么恢复？锚点呢？）。现在 `events` 只记 `after`；等事件形状稳定、真的需要撤销再做，不做半截的 |
| `read_paper_text` / `read_paper_outline` | 依赖"正文归档成块"，新版还没有 HTML 归档（P5）。机制（按块取 + `next_offset`）已经记在这张表里，实现时照抄形状 |
| `pick` 参数投影 | 旧版其实也没做成通用机制（只有零散用处）。真需要时再评估 |
| 日报 / 推荐流 / 主题 / 期票 | 产品形态已废弃，见 [设计总纲](设计-总纲.md) |
