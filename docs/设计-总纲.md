# PaperPilot 设计总纲

> 本文是设想的唯一来源。施工以本文为准，不以任何既有实现为准。
> 本文不描述"以前是什么样、现在改成什么样"——只描述这个软件应该是什么样。

---

## 1 定位

PaperPilot 是一个**本地论文台账 + 兴趣画像 + 能力层**，服务对象是"在对话框里问话的人和帮他干活的 AI"。

一句话：**代码负责记账，AI 负责出结果，人负责提问。**

### 1.1 代码负责什么

| 职责 | 说明 |
|---|---|
| 论文台账 | 每篇论文一行，记录它是什么、我读过什么、我对它做过什么 |
| 兴趣画像 | 把人的行为沉淀成三维权重，可读、可重算、可衰减 |
| 扫描账 | 记下"扫过哪里、扫到什么"，防止重复劳动 |
| 能力层 | arXiv 客户端、检索语法、日历窗、打分、抽样、引文、全文、批注 |
| 呈现 | 把 AI 写的稿子渲染成页面；把状态摊开给人看 |

### 1.2 代码不负责什么

- 不预设任务。没有"日报""推荐流""每日必读"这些产品形态。
- 不替人决定看什么。排序函数是**库函数**，谁调都一样，调不调、怎么调由 AI 决定。
- 不做定时产出。要时效性就说一句"看最近的"。
- 不在代码里写死"每次给几篇""必须有几成探索位"。这些是请求的一部分，不是软件属性。

### 1.3 三条硬边界

1. **唯一操作入口是对话框。** 人想干什么就说，AI 用工具做，结果写成稿子。
2. **页面分两类。** AI 写的展示页（线性、网络）与人看的控制页（画像池、仪表盘、设置）。
3. **结果只有一种原语：草稿。** 不存在第二种"产出物"。

## 2 四个核心概念

### 2.1 论文台账（库）

**库里的一行 = 一篇论文存在过。** 仅此而已。

- 进库不等于"被认可"，也不等于"被处理过"。**没建卡的论文就是晾着**，可以一直晾着。
- 晾着是合法状态，不是待办事项。详情页会明确显示"没建卡"。
- 库没有淘汰动作。不需要的论文不建设即可，不删除——删除会连带毁掉人积累的东西，而不删的代价只是行数。
- 防重复抓取由 `arxiv_id` 唯一约束天然完成，不需要额外的"已扫"标记。

一篇论文在库里可以挂这些东西（都可以为空）：

| 类别 | 内容 |
|---|---|
| 元数据 | 标题、作者、分类、主分类、发布日期、arXiv 链接、PDF 链接 |
| 发现方式 | `found_by`：首次被谁用什么方式扫到的 |
| AI 卡 | 关键词（terms）、TL;DR、问题、方法、结论、贡献 |
| 评分 | 分数、评级、理由（有历史） |
| 人的状态 | 收藏、已读、跳过 |
| 人的文字 | 笔记（多条）、原文批注 |
| 正文 | 是否已归档 HTML 正文 |
| 引文 | 被引数、库内被引次数、指向与来自的边 |

### 2.2 草稿

**草稿 = 一次需求的产物，由 AI 命名，名字就是情景。**

- `1019 日报`、`光镊搬运近三个月`、`随机十篇`、`里德堡 XY 谱系` —— 名字承担了"这次想干什么"的全部语义，因此不需要再设任务类型字段。
- 一份草稿属于线性页或网络页，**不混合**。
- 快照语义：一次产出就是一份草稿。不做"往旧草稿里追加"。
- AI 可建、可写、可改名、可删；人在设置页可改名、可删、可指定默认显示哪一份。

### 2.3 兴趣画像

把人的行为沉淀为三维权重（分类 / 词面 / 作者），带时间衰减。

- **信号是账本，权重是推导物。** 权重随时可以从信号重算，因此调参不改历史、换口径不毁数据。
- 权重只在**排序**时被使用，不参与"要不要抓"。抓什么由请求决定。
- 画像池页只读。人可以钉「锚点」（手工权重，不衰减），但不直接改学出来的数值。

### 2.4 扫描账

回答两个问题：**"这篇是怎么来的？"** 和 **"那个时间窗我扫过没有？"**

- 前者记在论文行：`found_by` 一行短字符串。
- 后者记在扫描日志：一次抓取一条，带时间窗与分类明细。
- 空的时间窗没有论文行，所以只能靠日志回答——这是两处记账而不是一处的原因。

## 3 Web 五页

| 页面 | 作者 | 内容 | 关键交互 |
|---|---|---|---|
| **线性页** | AI | 论文条目按顺序排列，每条一张卡 | 选草稿、点进详情 |
| **网络页** | AI | 条目间的关系：上下层、分组、连线、布局 | 选草稿、点进详情 |
| **画像池** | 人看 | 三维权重、衰减后读数、来源占比、熵、锚点 | 增删锚点 |
| **仪表盘** | 人看 | 事件流、AI 成本、扫描记录、库规模、信号漏斗 | 筛选、翻页 |
| **设置** | 人控 | 两页的草稿管理 + 系统参数 + 写权 | 改名/删/设默认/改配置 |

**叶子页：论文详情。** 不属于五页导航，从任一条目点进去。目标是把这篇论文的**全部状态一次摊开**：元数据、AI 卡、评分历史、收藏/已读/跳过、笔记、批注数、发现方式、引文关系、它出现在哪些草稿里、以及"没建卡"时的补卡入口。

### 3.1 线性页

- **左侧草稿栏**：列出本页所有**线性**草稿的标题（条数、更新时间、哪份是默认）。点一条就打开那一条（`?draft=<id>`），当前那条高亮。草稿按 `kind` 分家——线性页永远看不到网络草稿，反之亦然；跨页指定一个 id 会**落回本页默认**，不串页也不报错。
- 默认显示"本页默认草稿"（在设置里指定）。没有默认草稿就是空状态，提示"去对话框里说一句"。
- 每张卡：标题（**点标题进详情**）、作者与分类、日期、AI 一句话评语、关键词、收藏态、无卡标记。
- 卡片上的按钮只做**人的动作**，一共四个：`arXiv 原文`（记 outbound）、`⬇ PDF`（记 download）、`收藏`、`不感兴趣`。
  - **没有"详情"按钮**：标题本身就是链接，多一个按钮只是多一个可点错的靶子。
  - **没有"标记已读"按钮**：实测旧版近一个月零点击，而"读没读"已由 view / outbound / download 三个自动埋点覆盖。让人去维护一个系统已经自动记过的状态，是把负担从程序转移给人。
  - 出站链接必须**经过本站**（`/papers/{id}/go`、`/pdf`）：直接给 `arxiv.org` 超链接会绕过系统，把权重最重的两个信号永久饿死。
  - 出站链接一律 `target="_blank"`：新标签页先请求站内路由（记信号）再 303 到 arXiv，**当前面板页不动**。否则点一下就离开了工作台，回来还得重新导航。

### 3.2 网络页

- **左侧草稿栏**：只列本页的**网络**草稿，规则同线性页。
- 同样由默认草稿驱动，渲染器只消费草稿里的 `network payload`。
- 渲染器自己写一份，只认这一种输入格式，不复用任何通用图组件。
- 内容来源不设限：引文上游/下游、共引相似、时间脉络、分组叙事，都由 AI 在写草稿时决定形状。

### 3.3 画像池

只读展示：三维 top 权重、衰减后的实际读数、每个维度的来源占比（行为/锚点）、分类熵（茧房哨兵）、最近若干条信号。锚点可增可删。

### 3.4 仪表盘

事件流（可筛操作者/操作类型）、AI 调用与成本、扫描批次（时间窗、分类、请求数、命中数）、库规模与增长、信号漏斗。**只读**，不做操作。

### 3.5 设置

- 草稿管理：列表（按页分组）、改名、删除、设为该页默认。
- 系统参数：阈值、抓取参数（每日页数、请求上限）、衰减半衰期、写权。
- 数据：种子导入、导出、重建权重。

### 3.6 启动行为

被框架拉起时，工作台在端口就绪后**自动在浏览器里打开**——"启动就把人的面板带到眼前"。
判定规则显式：`--open` 强制开、`--no-open` 强制不开、默认 `auto` = 只在被框架拉起时开
（框架注入 `MECHA_SOFTWARE_ROOT` / `MECHA_INITIAL_MODE` 即为被拉起）。
端口被占时**不半启动**：先报错退出，避免"工具面起来了、人面没有"的假绿。

## 4 数据模型

SQLite + WAL。六张核心表，全部以 `arxiv_id` 或自增 id 为主键；**没有任何表依赖"某次页面产出"而存在**。

### 4.1 papers

```
id, arxiv_id UNIQUE, version, title, abstract,
authors JSON, categories JSON, primary_category,
published_at, updated_at, pdf_url, abs_url,
found_by TEXT, first_seen_at
```

`found_by` 例：`region:quant-ph@2026-03`、`query:"neutral atom"@2026`、`author:王@2026`、`id:fetch`。

### 4.2 cards（一篇一行）

```
paper_id PK, tldr, problem, method, results, novelty,
terms JSON, model, written_at
```

卡是"读过摘要"的物证。覆盖式：同一篇再写卡就替换，历史留在事件流里。

### 4.3 readings（一篇一行）

```
paper_id PK, read, starred, skipped, updated_at
```

### 4.4 notes / marks

```
notes: id, paper_id, content, created_at
marks: id, paper_id, block_id, quote, body, kind, color, status, created_at
```

### 4.5 drafts

```
id, kind(linear|network), title UNIQUE, note,
payload JSON, author, created_at, updated_at
```

### 4.6 events（唯一日志，只追加）

```
seq, ts, actor(human|ai|system), op, target, payload JSON
```

- 信号 = `op` 形如 `signal:star`、`signal:view` 的行。**画像从这张表重算。**
- 扫描批次 = `op='scan'`，payload 带 `regions`、`days`、`requests`、`hits`。
- 人的动作、AI 的写操作、系统迁移，全部进这张表。它是仪表盘的数据源，也是回放的唯一依据。

### 4.7 派生表

```
profile_weights: kind, key, w, source, hits, updated_at   -- 可从 events 全量重算
citation_edges: src, dst, kind, year, citations, influential
paper_html: paper_id, status, path, fetched_at
settings: key, value
ai_calls: id, ts, purpose, tokens, cost
```

### 4.8 关系要点

- 所有从属表挂 `paper_id`，而 `papers` 永不被批量删除 ⇒ 不存在级联删除问题。
- 草稿只存 `arxiv_id`，不存 `paper_id`：换库、重建库都不影响草稿。
- 一张论文可以出现在任意多份草稿里；"它进过哪些稿"由草稿反查，不在论文行上冗余。

## 5 草稿协议

### 5.1 线性 payload

```json
{
  "entries": [
    {"arxiv_id": "2610.25020", "why": "运动态保真的光镊搬运，直接对口阵列规模化", "group": ""}
  ]
}
```

- 顺序即呈现顺序，`entries` 的数组次序就是页面次序。
- `why` 是 AI 写的**一句为什么**，必填。它是这个页面的灵魂：没有理由就不该出现在稿子里。
- `group` 可选，用于分段小标题。

### 5.2 网络 payload

```json
{
  "nodes": [{"arxiv_id": "…", "label": "…", "group": "…", "layer": -1}],
  "edges": [{"src": "…", "dst": "…", "kind": "cites|extends|similar|claim", "note": "…"}],
  "layout": {"mode": "layer|timeline", "sides": "both|up|down", "label": "auto"}
}
```

- `layer` 为负表示上游、正表示下游、0 表示本体。
- 布局只是提示，渲染器可以兜底。

### 5.3 体检

写草稿的回执必须带三项体检，**只报不拦**：

| 项 | 含义 |
|---|---|
| `no_card` | 条目里有多少篇没写过卡（= AI 没读过摘要） |
| `recently_shown` | 有多少篇已在别的草稿里出现过（近 N 天） |
| `top_share` | 单一分类最高占比 |

界面上对应地把「无卡」标在卡片上。这样"没读过就推"会自己露出来，而不是靠谁记得检查。

### 5.4 默认草稿

设置里为线性页、网络页各存一个默认草稿 id。页面无参数时渲染它。没有默认就渲染空状态。

## 6 能力层（工具面）

工具的划分原则：**以能力命名，不以任务命名。** 一个工具的存在理由应该是"这件事只有代码能可靠地做"，而不是"某个产品流程需要这一步"。

### 6.1 抓取与台账

| 工具 | 作用 |
|---|---|
| `fetch_papers(regions?, windows, mode)` | 按分类 × 日历全域扫，落账，记扫描日志 |
| `fetch_by_query(queries, windows, limit)` | 按检索式扫（任意语法），落账 |
| `fetch_paper(arxiv_id)` | 单篇拉入 |
| `fetch_html(arxiv_id)` | 归档正文，精读的前置 |
| `sample(window, n, mode)` | 抽样：`recent` / `random` / `adjacent` / `by_author` / `far` |

### 6.2 阅读与卡

| 工具 | 作用 |
|---|---|
| `search_papers(q, filters)` | 库内检索（标题/摘要/卡） |
| `search_fulltext(q)` | 跨篇正文检索 |
| `read_paper(arxiv_id)` | 元数据 + 卡 + 状态 |
| `read_text(arxiv_id, section?, block?)` | 正文分块读 |
| `read_outline(arxiv_id)` | 章节树 + 块 id |
| `write_card(arxiv_id, tldr, problem, method, results, novelty, terms)` | 写卡 |

### 6.3 打分与排序

| 工具 | 作用 |
|---|---|
| `score(arxiv_ids)` | 按画像给分与理由 |
| `rank(arxiv_ids, by?)` | 返回有序列表 |

打分是纯函数式能力：给一批 id，返回分数与"为什么"。不生成任何东西。

### 6.4 人的动作

`star` / `mark_read` / `skip` / `add_note` / `record_signal`。AI 可代声明，与网页点击同表同权。

### 6.5 兴趣

`read_profile` / `add_anchor(dimension, key, weight)` / `remove_anchor` / `recompute_weights`。

### 6.6 草稿

| 工具 | 作用 |
|---|---|
| `write_draft(kind, title, note, payload, draft_id?)` | 新建或整份替换，回执带体检 |
| `read_draft(id?|title?)` | 读一份（默认最新） |
| `query_drafts(kind?)` | 列清单（id/title/时间/条数） |
| `rename_draft(id, title)` | 改名 |
| `delete_draft(id)` | 删除 |

### 6.7 引文与网络素材

`sync_citations` / `sync_cited_by` / `read_references` / `read_citations` /
`related_papers` / `upstream_clusters`。前两个只负责把边拉进图，后四个读图。

### 6.8 精读

`annotate` / `verify_marks` / `update_mark` / `resolve_mark` / `capture_shot` /
`query_shots`。（**尚未实现**）

### 6.9 系统

`read_config` / `set_config` / `read_activity` / `read_status`。

### 6.10 工具面的自检规则

- 名字必须合框架的形状律：snake_case、**动词 + 宾语**，禁 `get_` / `list_`
  （官方惯例 `read_*` / `query_*`），禁项目前缀。
- **写工具由命令投影**，不手抄第二份；只读工具直接定义。
- 出现"只在某个页面流程里用得上"的工具，就该合并到别的工具的参数里。
- 工具数量上限：**不超过 50 个**（当前 35 个）。超过就说明还在用工具编码流程。

## 7 兴趣画像机制

### 7.1 信号 → 权重

每个信号对一个论文的全部特征（分类、作者、关键词、标题词）按权重累加：

| 信号 | 权重 |
|---|---|
| view | +0.3 |
| outbound | +0.5 |
| download | +0.8 |
| read | +0.6 |
| star | +1.0 |
| skip | −1.5 |
| uninterested | −2.0 |

权重表放配置里，可改。

### 7.2 衰减

读时衰减，不写时衰减：

```
w_now = w × 2^(−age / half_life)
```

默认 `half_life = 30 天`，可配。好处是历史不动，口径随时可换。

### 7.3 锚点

人手工钉的权重单独记（`source='anchor'`），不衰减、不参与重算。用于表达"这个方向我永远关心"。

### 7.4 重算

`recompute_weights` 清空派生表，按事件流重放。**任何时候画出来的画像都必须是重算得出来的**——这是"权重是推导物"的检验标准。

### 7.5 画像的唯一消费方

排序与抽样。它不决定抓什么，也不决定推什么。判断"该不该出现"永远是 AI 在那次请求里的事。

## 8 扫描账

### 8.1 论文行上的记法

`found_by` 只记**首次**发现方式，短、可解析、不增长：

- `region:quant-ph@2026-03-07` —— 扫这一天的这个分类时第一次见到
- `query:"neutral atom"@2026` —— 检索式命中
- `author:某某@2026` —— 作者监控
- `id:2610.25020` —— 直接点名拉入

### 8.2 日志上的记法

每次批量抓取写一条 `scan` 事件：

```json
{"source": "region", "regions": ["quant-ph", "physics.atom-ph"],
 "days": ["2026-03-07", "2026-03-08"], "requests": 8, "hits": 41, "new": 37}
```

`days` 明细是回答"这个窗扫过没有"的唯一依据，所以要存；条数等于批次数，规模天然克制。

### 8.3 使用方式

- 要扫某个窗口前，先问日志：已覆盖的日期跳过，只补缺口。
- 重复扫同一窗口不产生副作用（唯一约束挡住了重复行），但日志会多一条——这是可接受的。

## 9 交互范式

### 9.1 三个典型

**"看看昨天有什么"**
→ `fetch_papers(windows="昨天", regions=画像 top)` → `score` → 取前十 → `write_card` 逐篇建卡 → `write_draft(kind=linear, title="1024", entries=带 why 的前十)` → 前端就出现了。

**"随机给我十篇"**
→ `sample(window="近一年", n=30, mode="random")` → 过掉近 N 天已出现过的 → `score` 只用来筛掉明显不相关的 → 建卡 → `write_draft(title="随机十篇")`。

**"这篇的后续工作"**
→ `sync_cited_by` + `citations` → `write_draft(kind=network, title="2610.25020 的引用者", nodes/edges/layout)`。

### 9.2 AI 的四条纪律

1. **进稿必有卡。** 没用卡说明没读摘要，体检会抓出来，界面上也标着。
2. **不重复端。** 写稿前先看 `query_drafts` 里近期的条目，同一篇别连着出现。
3. **命名即情景。** 名字要让人半年后一眼想起当时要什么。
4. **理由必填。** 每条线性条目都要有一句为什么；写不出为什么，说明它不该进稿。

## 10 工程结构

```
Get Paper/
  mecha_site.py           站点声明：怎么被 mecha 起起来（数据，不是逻辑）
  docs/
  src/paperpilot/
    domain 层            config / ids / db / ledger / repo / scoring / drafts
    infra 层             arxiv_client / scholar
    mecha_adapter/       mecha 接线（唯一接触框架的地方）
      config.py            可写配置 schema + 校验 + 种入 Gate
      scope.py             作用域与写权
      queries.py           只读查询（Surface.QUERY）
      commands.py          有副作用的动作（CommandSpec + handler）
      tools.py             AI 能力面（读工具直定义，写工具由命令投影）
      monitor.py           监控摘要 + cockpit 端点
      stack.py             装配点
      hub.py               进程入口：四个面
    web/                 五页 + 叶子页（人面）
  scripts/import_legacy.py
  tests/
```

技术选型保持克制：FastAPI + SQLite(WAL) + Jinja 服务端渲染 + 少量原生 JS。
不引入前端框架、任务队列、第二套 ORM。

### 10.1 与框架的边界

| 归框架 | 归项目 |
|---|---|
| 写权模式、作用域、Gate、审计、operation_id | 谁能写什么（scope 表） |
| 命令/查询/工具/宿主的接线与投影 | 工具语义、参数、业务校验 |
| 端点、端口文件、就绪判据、监控传输 | 页面、领域数据、领域页面 |
| 长任务、产物引用 | 并发上限、检查点、结果落点 |

三条落地纪律：

1. **写只有一条路**：命令 → Gate → 领域。Web 与 AI 只是通道不同（`invoke_human` / `invoke`）。
2. **账只有一本**：`events` 表既是框架 History 的落地，也是项目账（信号 / 扫描 / 投递），
   共用同一个 seq；两边靠 `operation_id` 对账。
3. **端点只有一处真值**：端口一律 `port=0` 回读后写端口文件，数字不进日志、不给 AI 看。

### 10.2 无历史包袱规则

- 不写兼容层，不做旧字段别名，不保留"为了不破坏 X"的分支。
- 需要改动的模块就重写，不迁移。
- 数据导入是一次性脚本，放在 `scripts/`，不进运行时。
- 任何模块如果必须解释"为什么它长这样"，说明它该重写。

## 11 阶段计划

| 阶段 | 内容 | 产出 |
|---|---|---|
| **P0** | 骨架：配置、SQLite、事件日志、arXiv 客户端、mecha 工具注册 | 能跑起来，空页面 |
| **P1** | 台账：papers/cards/readings/notes、抓取与扫描账、详情页 | AI 能抓、能读、能建卡、能看 |

## 附录 A 种子数据导入

从既有 SQLite 导入**数据**，不导入任何页面产出物。一次性脚本，目标库是新 schema。

| 目标表 | 来源 | 处理 |
|---|---|---|
| `papers` | 全部论文行 | 元数据直搬；`found_by` 置 `legacy`；不带任何状态字段 |
| `cards` | 每篇最新一份总结 | tldr/problem/method/results/novelty/terms 直搬，`model` 保留 |
| `readings` | 已读/收藏/跳过 | 直搬 |
| `notes` | 笔记 | 直搬 |
| `marks` | 批注 | 直搬 |
| `events` | `op` 形如 `signal:*` 的行 | 作为信号账本导入，保留原时间戳 |
| `citation_edges` | 引文边 | 直搬 |
| `profile_weights` | — | **不导入**。导入信号后由新代码重算，用来验证口径一致 |

不导入：任何与页面产出物相关的表。它们承载的是产品形态，而形态不迁移。

导入后必须做的两件事：

1. `recompute_weights()`，与来源库的权重做一次量级比对，偏差应只来自衰减口径差异。
2. 抽查 20 篇有收藏/笔记的论文，确认人的数据全部到位。
